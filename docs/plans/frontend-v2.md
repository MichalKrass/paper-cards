# Paper Cards 前端与三层阅读 V2 计划

## 1. 文档状态

- 状态：已确认，进入本地实施
- 目标版本：V2
- 实施分支：`codex/frontend-v2`
- 线上发布：完成本地实现、自动测试和视觉确认后，由用户确认是否合并部署
- 参考方向：[Hugging Face Daily Papers](https://huggingface.co/papers) 的清爽、低装饰、内容优先风格

本计划是第一版 `PLAN.md` 的增量改版方案。原文件保留为 MVP 的设计和实施记录，不覆盖历史。

## 2. 改版目标

在不更换 Astro、GitHub Pages、JSON 数据源和现有搜索架构的前提下，把网站从“两层重信息卡片”升级为三层渐进阅读：

1. **论文速览**：快速形成第一印象。
2. **论文卡片**：严格按既定 22 个维度建立结构化理解。
3. **章节精读**：按原论文实际章节顺序阅读总结，并在必要时结合图表。

同时将米黄色、红色、粗边框、衬线大标题的编辑出版风格，改为白色、浅灰、暖黄色点缀、无衬线字体和轻边框的工具型界面。

## 3. 范围

### 3.1 本轮包含

- 首页视觉重构。
- 第一层速览卡片瘦身。
- 搜索、筛选、排序界面简化。
- 第二层严格覆盖 `论文卡片格式.txt` 的 22 个维度。
- 第三层章节精读页面和内容格式。
- 第三层完整、草稿和未生成状态。
- 至少一篇真实论文的代表性章节精读内容。
- 手机、平板和桌面响应式适配。
- 数据校验、单元测试、端到端测试、无障碍和视觉检查更新。
- README 和项目范围说明更新。

### 3.2 本轮不包含

- PDF 导出和打印布局。
- 登录、在线编辑和个人笔记。
- 阅读进度跨设备同步。
- 微信自动采集和定时生成。
- 评论、投票、点赞和社区投稿。
- 语义搜索和推荐系统。
- 服务端数据库或运行时 API。

## 4. 当前问题

- 首页大型介绍区最小高度约 400px，第一屏不能尽快进入论文浏览。
- 卡片最小高度约 510px，带有指标、证据、核验状态和多个标签，首层信息偏重。
- 当前视觉使用米黄色底、红色强调、黑色粗边框、硬投影和巨型编号，不符合新的清爽参考风格。
- 第一层没有同时明确显示完整发布日期、主要机构和统一领域。
- 当前详情页虽然基本覆盖 22 个字段，但字段名称和组合方式未完全按原格式显示。
- 当前没有章节总结、章节顺序、图表来源和原文定位的数据结构。
- PDF 仍是界面、文档和自动测试的一部分，与 V2 范围冲突。

## 5. 信息架构

| 层级 | 用户名称 | 核心问题 | 地址 |
| --- | --- | --- | --- |
| 第一层 | 论文速览 | 这是什么论文，是否值得点开？ | `/paper-cards/` |
| 第二层 | 论文卡片 | 从固定维度看，它做了什么、价值如何？ | `/paper-cards/papers/<id>/` |
| 第三层 | 章节精读 | 各章节具体讲了什么，论证如何展开？ | `/paper-cards/papers/<id>/reading/` |

保留现有第二层地址，避免旧链接失效。第三层使用新地址。三层之间使用清楚的面包屑和返回入口。

## 6. 视觉规范

### 6.1 视觉语言

- 页面背景：白色或极浅灰。
- 内容表面：白色。
- 主文字：接近黑色的中性灰。
- 次要文字：中灰。
- 边框：浅灰细线。
- 强调色：暖黄色，只用于焦点、选中状态、领域标签和小面积提示。
- 字体：系统无衬线中文与西文字体。
- 圆角：控件 8px，卡片 12px 左右。
- 阴影：默认无阴影，悬停只使用很轻的层次变化。
- 动效：100–160ms 的颜色或位移变化；尊重减少动态效果设置。

### 6.2 明确移除

- 巨型首页标语。
- 巨型卡片序号。
- 黑色硬投影。
- 红色顶部装饰条。
- 大面积衬线标题。
- 过强的全大写与等宽字体装饰。
- 与阅读无关的渐变、插画和动画。

### 6.3 响应式

- `1440 × 900`：两列速览卡片，第二、三层限制正文宽度。
- `768 × 1024`：单列宽卡片；第二层两列字段按空间自动降级。
- `390 × 844`：单列；搜索优先；筛选默认收起；章节目录可展开。
- 所有视口不得出现整页横向滚动。

## 7. 第一层：论文速览

### 7.1 页面顺序

1. 紧凑站点导航。
2. 小型页面标题、论文数量和最后更新时间。
3. 主搜索框。
4. 筛选按钮、当前筛选标签、结果数和排序。
5. 论文卡片列表。
6. 无结果状态和数据来源说明。

### 7.2 单张卡片只显示

- 论文原始标题。
- 可选中文标题。
- 完整发布日期。
- 最多两个主要机构。
- 主领域和最多两个辅助标签。
- 一句话总结。

正常论文不显示证据和维护状态；只有 `draft` 或 `needs_review` 显示轻量警告。首层不再显示主要指标、开源状态、复现难度和大段标签。

整张卡片为一个可点击、可键盘聚焦的链接，不嵌套其他交互。建议高度约 180–240px。

### 7.3 搜索和筛选

- 搜索框始终可见。
- 主筛选：领域、年份、机构。
- 更多筛选：证据等级、核验状态。
- 已选条件显示为可单独移除的标签。
- 手机端筛选默认收起。
- 默认按论文发布日期从新到旧排序。
- URL 保存搜索、筛选和排序状态，浏览器返回后恢复。

## 8. 第二层：论文卡片

第二层保留现有地址，但页面改为结构紧凑的标准卡片。

### 8.1 顶部

- 论文标题。
- 机构与作者。
- 发布日期和领域。
- 一句话总结。
- `进入章节精读`、`打开原论文` 和 `返回论文库`。

### 8.2 22 个维度

页面必须使用以下原始名称，不得遗漏：

1. 标题
2. 机构与作者
3. 发布日期
4. 任务
5. 应用场景
6. 解决的问题
7. 核心方法
8. 模型结构
9. 训练策略
10. 数据配方
11. 训练集与测试集
12. 主要指标
13. 相对上一代方法的变化
14. 真正有价值的创新
15. 是否开源以及开源地址
16. 代码成熟度
17. 复现难度
18. 算力需求
19. 工业落地价值
20. 商业价值判断
21. 局限
22. 后续值得关注的问题

视觉分组：

- 基本定位：1–7
- 技术与实验：8–14
- 工程与价值：15–20
- 边界与后续：21–22

所有字段默认可见。普通字段控制在 1–3 句话，列表控制在 1–4 个要点，主要指标只保留能够支撑结论的核心结果。未确认内容统一显示“未确认”。

来源、证据范围和更新时间单独置于页面末尾，不占用 22 个维度。

## 9. 第三层：章节精读

第三层按照每篇论文自己的原始章节顺序展示，不套用固定目录。例如：

```text
Abstract
1. Introduction
2. Related Work
3. Method
4. Experiments
5. Limitations
6. Conclusion
Appendix
```

### 9.1 每个章节

- 原始章节编号和标题。
- 中文章节概括。
- 2–5 个关键要点。
- 该章节在整篇论文中的作用。
- 必要时加入核心图或表。
- 对应页码、章节号或图表编号。

### 9.2 图文要求

- 只展示真正帮助理解方法或实验结果的图片。
- 每张图片提供中文解释、替代文本、原始图号和出处。
- 优先使用允许公开展示的论文图表或自绘示意图。
- 不镜像整篇受版权保护的论文，不使用不稳定热链。
- 图片使用响应式尺寸和延迟加载。

### 9.3 导航与状态

- 桌面端提供固定章节目录。
- 手机端提供紧凑的章节目录展开控件。
- 章节正文默认展开，目录负责跳转。
- 页面提供 `返回论文卡片` 和 `打开原论文`。
- 没有章节精读内容时，第二层显示“章节精读尚未生成”，不产生空白页面或无效链接。

第三层只有在读取过论文全文后才能标记完成。不得用摘要证据冒充完整章节总结。

## 10. 数据组织

继续使用现有 JSON 作为第一、第二层的唯一结构化事实源，并增加适合长内容的章节文件：

```text
data/papers/<paper-id>.json
content/reading-notes/<paper-id>.md
public/papers/<paper-id>/figures/
```

- JSON：论文身份、速览字段和 22 维卡片。
- Markdown：按真实章节顺序保存长篇总结。
- figures：经过筛选的原论文图表或自绘示意图。

章节文件至少记录：

- 论文 ID。
- 原论文链接和版本。
- 全文证据范围。
- 生成日期和复核状态。
- 章节顺序。
- 图表出处和替代文本。

第一层搜索索引不装入章节全文，避免数据量增加后影响首屏性能。

## 11. PDF 处理

- PDF 不属于 V2 验收条件。

## 13. 测试方案

### 13.1 数据校验

- 论文 ID 与章节文件的 `paperId` 一致。
- 章节编号和锚点唯一，顺序稳定。
- 完成状态必须有全文来源和至少一个章节。
- 图片必须有替代文本、图注和出处。
- 图片路径必须在允许的公开目录内。
- JSON 和 Markdown 中的可见文本不能注入脚本。

### 13.2 单元测试

- 搜索继续覆盖中英文标题、作者、机构、领域和标签。
- 领域、年份、机构、状态和证据筛选可组合。
- 排序稳定。
- URL 查询与界面状态互相恢复。
- 缺少章节内容时返回正确状态。

### 13.3 端到端测试

- 首页只显示速览字段。
- 整张卡片可通过鼠标和键盘进入第二层。
- 第二层出现全部 22 个字段标签。
- 第一层 → 第二层 → 第三层 → 返回路径正确。
- 第三层目录可跳转到章节。
- 第三层直链和刷新正常。
- 无章节内容时不显示无效链接。
- 搜索、筛选、排序、清空和无结果恢复正常。
- 页面中不再出现 PDF 导出入口。

### 13.4 视觉和无障碍

- 检查 `390 × 844`、`768 × 1024`、`1440 × 900`。
- 首页第一屏能够看到搜索和至少一张论文卡片。
- 无整页横向滚动、裁切、重叠和过密标签。
- 长英文标题和长机构名可以换行。
- 章节图表不超出正文。
- 键盘焦点清晰，标题层级连续，目录和筛选有可读标签。
- 不只依靠颜色表达草稿、状态或价值等级。

## 14. 验收标准

只有同时满足以下条件才可进入上线确认：

1. 第一层只展示标题、日期、机构、领域和一句话总结，以及必要的异常状态。
2. 首页第一屏不再被大型宣传区占据。
3. 新视觉统一为白色、浅灰、暖黄色、轻边框和无衬线风格。
4. 第二层逐项覆盖原始 22 个字段且名称一致。
5. 第三层按原论文章节顺序显示，不使用虚假统一目录。
6. 至少一篇真实论文具有完整章节总结和代表性图文。
7. 无章节内容的论文显示明确状态。
8. 搜索、筛选、排序和返回后的 URL 状态正常。
9. 三个目标视口无整页横向溢出。
10. 三层页面可通过键盘访问，无严重无障碍问题。
11. 页面不再显示 PDF 导出入口。
12. 数据校验、类型检查、单元测试、端到端测试和生产构建全部通过。
13. 用户确认视觉效果后才允许合并部署。

## 15. 失败恢复

- 所有工作在 `codex/frontend-v2` 分支进行。
- 每个层级使用独立、可回滚的提交。
- 失败构建不得部署。
- 线上版本异常时使用 `git revert` 回退 V2 提交。
- 不删除论文稳定 ID，不迁移到不可读的二进制数据源。
- GitHub Pages 始终保留上一次成功部署的产物。

## 16. 明确停止条件

完成新视觉、三层结构、搜索筛选适配、代表性章节样例、自动测试和视觉验证后停止。不得顺带实现 PDF、登录、在线编辑、笔记同步、微信自动采集、定时生成、社区互动、语义搜索或推荐系统。
